# Facebook-ээр нэвтрэх тохиргооны заавар

Web болон mobile-ийн код бэлэн. Энэ төсөлд **Meta Developer App хараахан үүсгээгүй** тул бодит Facebook нэвтрэлт идэвхжээгүй, Facebook-ийн жинхэнэ аккаунтаар туршаагүй байна.

Локал хөгжүүлэлтийн web дээр Facebook товч харагдах боловч тохиргоо дутуу үед дарах боломжгүй, тайлбартай байна. Production дээр тохиргоо бэлэн болоогүй бол товч нуугдана. Товч харагдаж байгаа нь Facebook нэвтрэлт ажиллаж эхэлсэн гэсэн үг биш.

## 1. Meta App үүсгэх

1. [Meta for Developers](https://developers.facebook.com/apps/) руу аппыг эзэмших Facebook аккаунтаараа орно. Шаардлагатай бол developer бүртгэлээ үүсгэнэ.
2. Шинэ апп үүсгэж, хэрэглэгчийг **Facebook Login**-оор нэвтрүүлэх зориулалтыг сонгоно. Дэлгэцийн нэршил өөрчлөгдсөн байж болох тул хэрэглэгчийн нэвтрэлтийн зориулалттай сонголтыг ашиглана.
3. Website-ийн Facebook Login тохиргоог нэмнэ. Сайтын үндсэн хаяг нь `https://www.tanaid-honoy.mn`. App Domains хэсэгт шаардлагатай `tanaid-honoy.mn`, `www.tanaid-honoy.mn` домайнуудыг оруулна.
4. **Valid OAuth Redirect URIs** хэсэгт дараах хаягийг төгсгөлийн `/` тэмдэгтэй нь яг хэвээр оруулна:

   ```text
   https://www.tanaid-honoy.mn/api/auth/facebook/callback/
   ```

5. Аппын нэр, зураг, холбоо барих имэйл болон дараах хаягуудыг тохируулна:

   | Талбар | Оруулах хаяг |
   |---|---|
   | Website | `https://www.tanaid-honoy.mn` |
   | Privacy Policy URL | `https://www.tanaid-honoy.mn/mn/privacy` |
   | User Data Deletion — зааврын хуудас | `https://www.tanaid-honoy.mn/mn/facebook/data-deletion` |

   Нууцлал болон мэдээлэл устгуулах хуудсуудыг эхлээд серверт байршуулж, гаднаас нээгдэж байгааг шалгана. Data Deletion талбарт **зааврын URL** гэсэн хувилбарыг ашиглана; энэ хуудас автомат callback endpoint биш.

6. Нэвтрэлт зөвхөн `public_profile,email` зөвшөөрөл хүснэ. Эхлээд аппын role-той хэрэглэгч эсвэл Meta-ийн test user-ээр туршина. Энгийн хэрэглэгчдэд нээхийн өмнө Meta dashboard дээр тухайн аппд үзүүлсэн access, review, verification шаардлагуудыг биелүүлнэ. Зөвхөн developer аккаунтаар нэвтэрсэн нь нийт хэрэглэгчдэд ажиллана гэдгийг батлахгүй.
7. **App ID**, **App Secret**-ээ backend серверийн орчны тохиргоонд хадгална. App Secret-ийг чат, frontend, mobile эсвэл Git-д оруулж болохгүй.

## 2. Backend-ийн тохиргоо

Backend ашиглаж байгаа орчны хувьсагчид дараах утгуудыг оруулна. Доорх жишээний App ID, App Secret хэсгийг өөрийн аппын бодит утгаар солино:

```dotenv
FACEBOOK_ENABLED=False
FACEBOOK_APP_ID=<өөрийн Meta App ID>
FACEBOOK_APP_SECRET=<өөрийн Meta App Secret>
FACEBOOK_GRAPH_VERSION=v24.0
FACEBOOK_REDIRECT_URI=https://www.tanaid-honoy.mn/api/auth/facebook/callback/
FRONTEND_URL=https://www.tanaid-honoy.mn
```

`v24.0` нь кодод тогтоосон хувилбар бөгөөд хамгийн шинэ хувилбар гэсэн үг биш. Meta dashboard дээр тухайн апп энэ хувилбарыг ашиглах боломжтойг шалгана.

Facebook-ийн хэрэглэгчийн таних дугаар нь тухайн Meta App-д хамаардаг. Нэвтрэлтийг ашиглаж эхэлсний дараа App ID-г дур мэдэн сольж болохгүй; сольбол өмнөх холболтуудыг шилжүүлэх төлөвлөгөө шаардлагатай.

Шинэ Facebook бүртгэл email кодоор баталгааждаг тул Gmail SMTP тохиргоо мөн ажиллах ёстой:

```dotenv
EMAIL_HOST_USER=<илгээгчийн Gmail хаяг>
EMAIL_HOST_PASSWORD=<Gmail app password>
DEFAULT_FROM_EMAIL=<илгээгчийн имэйл>
```

`DEFAULT_FROM_EMAIL`-ийг заавал тусад нь оруулахгүй байж болно; заагаагүй бол `EMAIL_HOST_USER`-ийг ашиглана.

## 3. Өгөгдлийн санг шинэчлэх

Backend-ийн орчинд дараах командыг ажиллуулна:

```sh
python manage.py migrate
```

Дараах миграциуд орсон байх шаардлагатай:

- `0052_unique_user_email`: email-ийг нэг хэлбэрт оруулж, давхардлыг хориглоно. Өмнө нь ижил email-тэй аккаунтууд байвал миграци зогсоно. Аккаунтуудыг автоматаар нэгтгэхгүй, устгахгүй; эзэмшлийг шалгаж давхардлыг шийдсэний дараа дахин ажиллуулна.
- `0053_facebook_login`: Facebook аккаунтын холболт болон түр нэвтрэх хүсэлтийг хадгалах хүснэгтүүдийг үүсгэнэ.

Өмнөх нууц үг сэргээх засварууд серверт анх орох үед нэвтэрсэн хэрэглэгчид нэг удаа дахин нэвтрэх шаардлагатай.

## 4. Web болон mobile-ийг турших

Хоёр платформ ижил HTTPS backend callback ашиглана. Утас системийн браузераар Facebook нэвтрэлтийг хийгээд `tanaidhonoy://facebook-callback` холбоосоор апп руу буцна.

**Meta-ийн Valid OAuth Redirect URI талбарт `tanaidhonoy://...` холбоосыг оруулахгүй.** Тэнд зөвхөн дээрх HTTPS backend callback-ийг бүртгэнэ.

Mobile дээр Facebook native SDK болон App Secret нэмэх шаардлагагүй. Одоо байгаа `expo-web-browser` болон `tanaidhonoy` scheme ашиглагдана. Development эсвэл дэлгүүрийн build дээр туршина; Expo Go дээр энэ урсгалыг ашиглахгүй. Web хэрэглэгчид Next.js сайтыг ашиглана; Expo-ийн web preview дээр Facebook товч харагдахгүй.

Эхлээд туршилтын сервер ашиглах нь тохиромжтой. Тэр сервер өөрийн HTTPS callback-тай, уг хаяг нь Meta дээр бүртгэлтэй байх ёстой. `FRONTEND_URL` нь туршилтын web-ийн хаяг, mobile-ийн API хаяг нь мөн туршилтын backend рүү заана.

Одоогийн код зөвхөн HTTPS callback зөвшөөрдөг. `localhost:3000` дээр товч, хуудасны харагдах байдлыг шалгаж болох ч Meta тохиргоогүйгээр бодит Facebook аккаунтаар нэвтрэхгүй.

Тохиргоо бэлэн болмогц туршилтын backend дээр `FACEBOOK_ENABLED=True` болгож, backend-ийг дахин асаана. Web/mobile нь `/api/auth/facebook/config/`-оос идэвхтэй эсэхийг уншдаг тул frontend/mobile-д Facebook-ийн тусгай public environment variable оруулахгүй.

Production дээр бодит тохиргоо, туршилтууд дууссаны дараа л `FACEBOOK_ENABLED=True` болгоно.

## 5. Аккаунт холбох зарчим

- Өмнө нь холбогдсон Facebook-ээр ороход тухайн аккаунтдаа нэвтэрнэ. Facebook-ийн email өөрчлөгдсөн ч шинэ аккаунт үүсэхгүй, системийн email болон профайлыг автоматаар солихгүй.
- Email өмнөх бүртгэлтэй таарсан ч шууд холбохгүй. Хэрэглэгч Google эсвэл нууц үгээрээ нэвтэрч, аль аккаунтдаа Facebook холбохоо баталгаажуулна.
- Facebook-ийн email өөр байсан ч өмнөх аккаунтаараа нэвтэрч холбож болно. Захиалга, хадгалсан зүйлсийг шилжүүлэхгүй; өмнөх аккаунтдаа үлдэнэ.
- Шинэ хэрэглэгч “шинэ аккаунт үүсгэнэ” гэдгээ сонгоод, Facebook-ээс ирсэн email-д илгээсэн зургаан оронтой кодоор баталгаажуулна. Үүсгэх мөчид email болон Facebook холболт давхардсан эсэхийг дахин шалгана.
- Facebook email дамжуулаагүй бол өмнөх аккаунтаараа нэвтрэх эсвэл эхлээд email-ээр бүртгүүлээд Facebook-ээ холбоно. Хуурамч email болон далд давхар аккаунт үүсгэхгүй.
- Өөр хүний аккаунтад холбогдсон Facebook-ийг шилжүүлэн авах, одоо байгаа Facebook холболтыг чимээгүй солих боломжгүй.
- Нэвтрэх хүсэлт эхэлснээс хойш 10 минут хүчинтэй. Нэвтрэх, холбох, email код оруулах үйлдлийг энэ хугацаанд дуусгана. Хугацаа дуусвал Facebook товчоор дахин эхлүүлнэ.
- Facebook-ээр шинээр үүсгэсэн аккаунт эхэндээ нууц үггүй. Дараа нь нууц үг сэргээх урсгалаар тухайн аккаунтдаа нууц үг тохируулж болно.

## 6. Хамгаалалт ба арчилгаа

OAuth state, нэг удаагийн солилцооны код, холбох тасалбарыг хэшлэж хадгалдаг. Браузер/төхөөрөмж дээр үүсгэсэн нууц verifier нь нэвтрэх хүсэлтийг эхлүүлсэн төхөөрөмжтэй нь холбоно. Facebook токеныг backend дээр шалгаад өгөгдлийн санд хадгалахгүй. Системийн JWT токенуудыг POST хариугаар буцаах бөгөөд redirect URL-д оруулахгүй.

Email кодыг дахин авахын өмнө нэг минут хүлээнэ. Нэг хүсэлтэд хамгийн ихдээ таван удаа код шалгуулна. Нэвтрэх endpoint-уудад хүсэлтийн тооны хязгаарлалт бий.

Хугацаа дууссан түр өгөгдлийг шинэ Facebook хүсэлт эхлэх үед цэвэрлэнэ. Хэрэглэгч цөөн үед ч түр мэдээлэл хуримтлагдахгүй байлгахын тулд сервер дээр дараах командыг тогтмол ажиллуулахаар тохируулна:

```sh
python manage.py cleanup_facebook_auth
```

Олон backend worker ашигладаг бол хүсэлтийн тооны хязгаарлалт нь бүх worker-т үйлчлэхийн тулд shared cache ашиглана. Анхдагч in-process cache нь worker тус бүрийг тусад нь хязгаарладаг. Reverse proxy болон monitoring дээр OAuth callback-ийн query string, auth хүсэлтийн body-г бүртгэхгүй байх тохиргоог шалгана.

Тусламжийн ажилтан Django admin-ийн `FacebookAccount` хэсгээс холболтыг харж, эзэмшил нь баталгаажсан хэрэглэгчийн хүсэлтээр салгаж болно. Зөвхөн Facebook холболтоо салгах хүсэлт гаргасан бол системийн аккаунт, захиалгыг устгахгүй. Хэрэглэгч өөр нэвтрэх аргатай, жишээлбэл нууц үгээ тохируулсан эсэхийг эхлээд шалгана. Аккаунтыг бүхэлд нь устгах хүсэлтэд одоогийн тусламж, нууцлалын журмыг мөрдөнө.

## 7. Нийт хэрэглэгчдэд нээхийн өмнөх шалгалт

Автомат тестүүд Meta болон SMTP-г орлуулсан тестийн хариу ашигладаг. Тэд бодит Facebook нэвтрэлт, имэйл хүргэлт, Meta-ийн зөвшөөрөл, утсан дээр апп руу буцах ажиллагааг батлахгүй.

```sh
python manage.py test core.test_facebook_login core.test_password_recovery core.test_api
```

Туршилтын web, iOS болон Android build дээр дараах урсгалыг шалгана:

- Шинэ Facebook хэрэглэгч → шинэ бүртгэл сонгох → email код → бүртгэл → профайл → гарах → Facebook-ээр дахин ороход ижил аккаунтдаа орох.
- Өмнөх Google/нууц үгийн аккаунт → өмнөх аргаар нэвтрэх → Facebook холбохоо баталгаажуулах → захиалга, хадгалсан зүйлс хэвээр үлдэх.
- Facebook-ийн email өөр эсвэл email зөвшөөрөл өгөөгүй үед өмнөх аккаунт холбох, эсвэл email-ээр бүртгүүлэх ажиллагаа зөв байх.
- Цуцлах, зөвшөөрөл өгөхгүй байх, буруу код, хугацаа дуусах, хуучирсан нэвтрэх токен, SMTP алдаа, өөр аккаунтын Facebook холбох оролдлого зэрэгт ойлгомжтой алдаа үзүүлэх.
- Утасны апп background болсон үед ч браузераас `tanaidhonoy://facebook-callback` руу зөв буцах. Web нь тохируулсан домайн руу ижил tab дотор буцах.
- Meta-ийн нийт хэрэглэгчдэд нээх тохиргоо дууссаны дараа app role-гүй энгийн Facebook хэрэглэгчээр нэвтэрч үзэх.
